# Project Context Index

This directory stores durable, token-efficient context about the ROS2 workspace (`/ws/ros_ws`), collected during code-base investigations so future work does not need to re-read large source trees. `/ws` is the project root; `/ws/ros_ws` is the ROS2 workspace root.

| File | What it covers |
|------|----------------|
| [repo-layout.md](repo-layout.md) | Top-level packages, which dirs are git submodules, build entry points. |
| [slam-package.md](slam-package.md) | `src/slam` (submodule): C++ SLAM compute nodes — class hierarchy (`SlamNode`, `BasaltSLAMNode`, `Slam`, `BasaltSLAM`), message typedefs, IMU/Frame data classes, key files & line refs. Also the managed lifecycle publishers, now activated by delegating to `SlamNode::on_activate`/`on_deactivate`, why the omission was invisible for so long (`rclcpp::Publisher::publish` is non-virtual and the members are declared as the base type), and the opposite ordering rules for the two base calls. |
| [basalt-node-cpp.md](basalt-node-cpp.md) | Detailed anatomy of `BasaltSLAMNode` (node.cpp/node.hpp): lifecycle callbacks, current members, IMU handling, and exactly what is missing for VISLAM. |
| [controllers-package.md](controllers-package.md) | `src/controllers` (regular pkg, ament_cmake + ament_python): the package layout including the C++ controllers, the entry-point script pattern and why it must spin a `MultiThreadedExecutor`, the module-level lookup tables and method inventory of `SLAMDriverNode`, and what `LifecycleControllerBase` supplies to both C++ controllers. |
| [launch-and-djinn.md](launch-and-djinn.md) | Launch-file graph for SITL + Basalt as **two independent stacks** (`basalt_slam_test.launch.py` is SLAM-only and no longer includes `sitl.launch.py`), the two argument-propagation traps (an undeclared argument is silently discarded; the forwarding key must match the declared name, hyphens included), which launch file owns which argument, and the four divergent copies of `topics_to_record`. |
| [slam-lifecycle-flow.md](slam-lifecycle-flow.md) | How the autopilot status → lifecycle transition flow works end-to-end, node names, service names, QoS. Leads with the **target-state reconciler pattern** both lifecycle managers now implement (target from vehicle phase, step table, one async transition per step, re-entered on completion) and its three correctness rules. Then the `SLAMDriverNode` flow with its concurrency model and the hold-until-disarm rule, and the `VideoLoggingDriver` flow with its latched target, the three surviving clause predicates, the three load-bearing properties, the arm-then-disarm teardown gap that is preserved deliberately, and the note that its formerly latent mutex races are now closed. Also the **workspace rule that no blocking call may sit in a node constructor** (with the one violation still standing) and how to mirror a managed node's state from `~/transition_event` (including the two traps: the transition label is not unique, and a rejected request publishes no event at all). |
| [rosbag2-recording-architecture.md](rosbag2-recording-architecture.md) | The full `rosbag2_transport` initialisation sequence (executor spinning first → `on_configure` → `make_writer` → `Recorder` → `record()` → `subscribe_topic`) and the timing consequence that nothing published before activation is captured unless latched; how `Recorder` **negotiates** QoS via `adapt_request_to_offers()`; how the trigger message came to be captured on both platforms (chain configure→activate on arming, plus latch `tello_state`) and the timing margin that makes it work; the thread-safe `rosbag2_cpp::Writer` injection API for genuinely synthetic messages; and why pause/resume, snapshot mode and blanket `topic_qos_profile_overrides` are the wrong tools. |
| [ros-qos-compatibility.md](ros-qos-compatibility.md) | QoS audit of every topic edge shared between `slam`, `controllers` and `sensors` (all now matching), the DDS offered-vs-requested matching rule, the rules this workspace follows — never *request* TRANSIENT_LOCAL, but *offering* it is safe and is the right fix for an edge-driven state topic; BEST_EFFORT for sensor streams — and why `/ap/status` needs no change in either SLAM back-end. |
| [simd-eigen-abi-mismatch.md](simd-eigen-abi-mismatch.md) | Why `basalt_slam_node` segfaulted inside `ld.so` during `on_activate`: `-march=native` in the `ext/basalt` subdirectory raises `EIGEN_MAX_ALIGN_BYTES` and changes `sizeof(basalt::Controller)` (1056 vs 1008) → heap overflow. Evidence commands, the `-march`-is-an-ABI-switch rule, the pin as shipped, and the other defects found alongside (all now fixed). Full tutorial: [`src/slam/context/SIMD.md`](../src/slam/context/SIMD.md). |

## Recent work

**2026-07-27 — SLAM lifecycle driven by `/ap/status`, on a target-state reconciler.** `SLAMDriverNode` was rewritten from an edge/branch tree that could not work under its own executor into a level-triggered reconciler with a push-based state mirror fed by `~/transition_event`, both SLAM controller entry points moved to a `MultiThreadedExecutor` with a stated concurrency model and one lock, the managed publishers in `BasaltSLAMNode` and `VisualSlamNode` are now activated, and `VideoLoggingDriver` was reorganised onto the same reconciler with no change to its recording behaviour. Change-record: [`/ws/plans/slam-lifecycle-ap-status-reconciler.md`](../../plans/slam-lifecycle-ap-status-reconciler.md).

**2026-07-25 — Basalt SLAM + SITL logging defect remediation.** Implemented across `slam`, `controllers`, `sensors` and `tello`: the Eigen/`-march` ABI pin, the `BasaltSLAMNode` correctness fixes (build blocker, IMU QoS), and the video-logging lifecycle rework that makes recording start at the arming edge on both autopilots with the triggering message itself captured. Change-record: [`/ws/plans/basalt-slam-defect-remediation.md`](../../plans/basalt-slam-defect-remediation.md).
